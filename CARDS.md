# Карточка 1

**Лицевая сторона:**
Требуется реализовать алгоритм сжатия данных RLE (Run-length encoding) для сжатия текстовых данных "на лету". Алгоритм должен эффективно обрабатывать потоковые данные, поступающие непрерывно, и работать со скоростью, не уступающей скорости поступления этих данных.

Конкретные требования к реализации:

1. Закодировать последовательности одинаковых символов длиной не менее 4 с помощью трехбайтовой конструкции: `<# (спецсимвол), число повторов, символ>`.
2. Обрабатывать символ '#' особым образом - всегда кодировать его, даже если он встречается одиночно.
3. Специально обрабатывать последовательности длиной более 255 символов: разбивать их на части по 255 символов и кодировать каждую часть отдельно.
4. Применить оптимизацию "сдвиг на 4": кодировать цепочку из 4 символов как `#\x00символ` вместо `#\x04символ` (где `\x00` - символ с кодом 0).

Режим работы программы (кодирование или декодирование), имя входного файла и имя выходного файла должны задаваться через параметры командной строки. Программа должна:

* Принимать текстовый файл на вход
* Выполнять кодирование/декодирование в соответствии с режимом
* Сохранять результат в указанный выходной файл
* Вычислять и выводить коэффициент сжатия как отношение длины исходного файла к длине сжатого файла

После кодирования и последующего декодирования исходный текст должен быть полностью восстановлен без потерь. Необходимо протестировать алгоритм на различных типах данных, включая текст с большим количеством повторяющихся символов (например, сетевые пакеты с длинными последовательностями нулевых байтов) и текст с малым количеством повторений.

**Обратная сторона:**
**Алгоритм:**

* Кодирование: Заменять последовательности одинаковых символов (длиной ≥4) на трехбайтовую последовательность: `<# (спецсимвол), число повторов, символ>`.
* Для последовательностей >255: разбивать на части по 255 символов.
* Символ "#" всегда кодировать (даже одиночный).
* Декодирование: При обнаружении '#' брать следующие два символа как количество повторов и сам символ.
* Оптимизация: Сдвиг на 4 - кодировать цепочку из 4 символов как #\x00символ.

# Карточка 2

**Лицевая сторона:**
На вход подается строка, состоящая из последовательности букв. Требуется выполнить два действия: 1) построить алфавит (т.е. множество всех различных символов исходной строки) и вычислить частоту появления каждого символа из этого алфавита; 2) рассчитать энтропию Шеннона для полученной таблицы частот согласно формуле H(X) = -∑(p_i * log_n(p_i)), где p_i - относительная частота i-го символа, n - размер алфавита (основание логарифма). Суммирование должно проводиться только для символов с ненулевой частотой. Энтропия представляет собой меру хаотичности/неопределенности данных и определяет минимальное среднее количество бит, необходимое для кодирования символа из заданного алфавита. Программа должна выводить построенную таблицу частот и вычисленное значение энтропии с точностью до 8 знаков после запятой.

**Обратная сторона:**
**Алгоритм:**

1. Построить алфавит символов (множество уникальных символов в строке)
2. Вычислить частоту каждого символа: `p_i = count_i / L`, где L - длина строки
3. Рассчитать энтропию по формуле: `H(X) = -∑(p_i * log_n(p_i))`
   * n - размер алфавита (основание логарифма)
   * Суммирование только для символов с ненулевой частотой
4. Интерпретация: Энтропия отражает меру хаотичности/неопределенности данных и минимальное среднее количество бит для кодирования символа.

# Карточка 4

**Лицевая сторона:**
Требуется реализовать стандарт IEEE 754 для представления чисел с плавающей запятой в формате float (32 бита). Программа должна работать в одном из двух режимов, задаваемых параметрами командной строки:

В первом режиме программа считывает из файла строку:

1. Если строку можно интерпретировать как число, то в файл записывается внутреннее представление этого числа в формате IEEE 754: 1 бит знака, 8 бит для порядка со смещением 127, 23 бита для мантиссы (с ведущей единицей, которая не хранится). Если число по модулю превосходит (2 - 2^-23) * 2^127, то записывается внутреннее представление бесконечности.
2. Если строку нельзя интерпретировать как число, то в файл записывается внутреннее представление не числа (NaN).

Во втором режиме программа считывает из файла строку, содержащую два числа, разделенных операцией + или -. Программа должна:

* Перевести оба операнда во внутреннее представление
* Выполнить сложение/вычитание над операндами в соответствии со стандартом IEEE 754
* Обработать все особые случаи: ноль (±0), бесконечность (±∞), NaN, денормализованные числа
* В файл записать результат во внутреннем представлении и в десятичном виде

Требуется реализовать алгоритм сложения чисел с плавающей запятой, включая выравнивание порядков, сложение мантисс, нормализацию результата и округление.

**Обратная сторона:**
**Алгоритм:**

1. **Для преобразования в формат float (32 бита):**
   * 1 бит знака (0 - положительное, 1 - отрицательное)
   * 8 бит для порядка со смещением 127
   * 23 бита для мантиссы (ведущая 1 не хранится)
2. **Обработка особых случаев:**
   * Ноль (±0): все биты порядка и мантиссы = 0
   * Бесконечность (±∞): все биты порядка = 1, мантисса = 0
   * NaN: все биты порядка = 1, мантисса ≠ 0
   * Денормализованные числа: все биты порядка = 0
3. **Для сложения:**
   * Выравнивание порядков операндов
   * Сложение/вычитание мантисс
   * Нормализация результата
   * Округление до 23 бит

# Карточка 5

**Лицевая сторона:**
Дана строка S длины n и строка T длины m (n ≥ m). Требуется найти все вхождения строки T в строку S, используя два метода: 1) алгоритм грубой силы (brute force); 2) метод хэширования с тремя вариантами хэш-функций (сумма кодов символов, сумма квадратов кодов, полиномиальный хэш Рабина-Карпа). Для алгоритма грубой силы необходимо последовательно сдвигать шаблон T по строке S и на каждом шаге сравнивать символы слева направо. Для хэш-методов требуется предварительно вычислить хэш шаблона, использовать рекуррентное вычисление хэшей для фрагментов S, и при совпадении хэшей проводить посимвольную проверку для обработки коллизий.

Необходимо провести три вычислительных эксперимента:

1. Последовательное увеличение длины текста: выполнить поиск паттерна "князь Андрей" в первом томе романа "Война и мир", затем в первых двух томах, первых трех томах и во всех четырех томах. Для каждого случая измерить время работы каждого метода.
2. Массовый тест с несколькими паттернами: для каждого тома романа "Война и мир" и для полного текста всех томов выполнить поиск трех паттернов разной длины: "князь", "князь Андрей", "князь Андрей Болконский". Для каждого сочетания (файл, паттерн, метод) измерить время работы и количество коллизий для хэш-методов.
3. Тест на синтетических данных: для строк text1 = 'a'^100 + 'b' и text2 = 'b' + 'a'^100 выполнить поиск паттернов pattern1 = 'a'^100 + 'b' и pattern2 = 'b' + 'a'^100. Этот тест демонстрирует слабые стороны простых хэш-функций (sum, sumsq) при работе с последовательностями одинаковых символов.

Все результаты экспериментов должны быть сохранены в CSV-файлы с указанием времени выполнения, количества совпадений, количества ложных срабатываний (для хэш-методов) и характеристик текстов и паттернов.

**Обратная сторона:**
**Алгоритмы:**

1. **Грубая сила (brute force):**
   * Последовательно сдвигать шаблон T по строке S
   * На каждом шаге сравнивать символы слева направо
   * При несовпадении сдвигать шаблон на 1 позицию
   * Сложность: O(n·m), где n - длина текста, m - длина шаблона
2. **Хэширование (метод Рабина-Карпа):**
   * Предвычислить хэш шаблона T
   * Использовать рекуррентное вычисление хэшей для фрагментов S
   * При совпадении хэшей проводить посимвольную проверку
   * Эффективные хэш-функции:
     * Сумма кодов символов
     * Сумма квадратов кодов
     * Полиномиальный хэш: ∑(code[i]·p^(m-i))

# Карточка 6

**Лицевая сторона:**
Дана строка S длины n и строка T длины m (n ≥ m). Требуется найти все вхождения строки T в строку S с использованием алгоритма Бойера-Мура, реализующего эвристику плохого символа. Алгоритм должен:

1. На этапе предварительной обработки шаблона T построить таблицу N последних (наиболее правых) вхождений каждого символа в шаблон T. Для символов, отсутствующих в шаблоне, значение в таблице должно быть равно 0.
2. На этапе поиска:
   * Начинать сравнение символов справа налево (с конца шаблона)
   * При обнаружении несовпадения (плохого символа) вычислять величину сдвига по формуле: max(m - N[char; T] - l, 1), где char - плохой символ, l - количество совпавших символов с правого конца шаблона
   * Если символ отсутствует в шаблоне или его последнее вхождение находится левее текущей позиции, сдвигать шаблон так, чтобы символ в тексте оказался правее шаблона
   * Если символ присутствует в шаблоне и его последнее вхождение находится правее текущей позиции, сдвигать шаблон так, чтобы последнее вхождение символа в шаблоне совпало с его вхождением в тексте
3. При полном совпадении шаблона с фрагментом текста зафиксировать позицию вхождения и сделать сдвиг на 1 позицию для продолжения поиска.
4. Провести сравнение эффективности алгоритма Бойера-Мура с алгоритмом грубой силы и хэш-методами на различных наборах данных, включая тексты "Войны и мира" с различными паттернами.

Особое внимание должно быть уделено тому, чтобы алгоритм никогда не сдвигал шаблон влево и обрабатывал все возможные случаи при работе с различными символами.

**Обратная сторона:**
**Алгоритм:**

1. **Предварительная обработка шаблона:**
   * Построить таблицу последних вхождений (эвристика "плохого символа")
2. **Поиск:**
   * Сравнение символов производится справа налево
   * При несовпадении вычисляется сдвиг:
     * Если символ не принадлежит T: сдвиг на m позиций
     * Если символ принадлежит T: сдвиг на max(1, m - N[char; T] - l), где l - количество совпавших символов
   * При полном совпадении: зафиксировать позицию и сдвинуть на 1
3. **Сложность:**
   * В лучшем случае: O(n/m), где n - длина текста, m - длина шаблона
   * В худшем случае: O(n·m)
   * Средний случай: O(n)

# Карточка 7

**Лицевая сторона:**
Дано множество шаблонов T = {T1, T2, ..., Tk} и строка S длины n. Требуется найти все вхождения всех шаблонов в строку S, используя алгоритм Ахо-Корасика. Алгоритм должен:

1. Построить префиксное дерево (бор) из всех шаблонов:
   * Корень дерева соответствует пустой строке
   * Каждый узел дерева представляет префикс одного или нескольких шаблонов
   * Листовые узлы помечаются соответствующими шаблонами, которые заканчиваются в этих узлах
   * Ребра дерева помечаются символами алфавита
2. Построить функцию отказа (fail-функцию) для каждого узла:
   * Для корня: fail-ссылка указывает на себя
   * Для узлов, находящихся на глубине 1: fail-ссылка указывает на корень
   * Для остальных узлов: fail-ссылка указывает на узел, соответствующий наибольшему собственному суффиксу префикса, представленного текущим узлом
   * Построение выполняется с помощью обхода дерева в ширину (BFS)
3. Построить функцию вывода для каждого узла:
   * Содержит все шаблоны, которые заканчиваются в данном узле или в узлах, достижимых по fail-ссылкам
   * Позволяет зафиксировать все совпадения при достижении узла в процессе поиска
4. Выполнить поиск по строке S:
   * Начать с корня дерева
   * Последовательно обрабатывать символы строки S
   * При отсутствии перехода по текущему символу следовать по fail-ссылкам
   * При достижении узла вывести все шаблоны из его функции вывода
   * Зафиксировать позиции всех вхождений шаблонов

Временная сложность алгоритма должна быть O(n + m + z), где n - длина текста, m - суммарная длина всех шаблонов, z - количество найденных совпадений. Программа должна обрабатывать случаи, когда один шаблон является подстрокой другого, и корректно находить все вхождения.

**Обратная сторона:**
**Алгоритм:**

1. **Построение бора (префиксного дерева):**
   * Каждый узел представляет префикс одного или нескольких шаблонов
   * Листовые узлы помечаются соответствующими шаблонами
2. **Построение функции отказа (fail):**
   * Для каждого узла определяется суффиксная ссылка (наиболее длинный собственный суффикс, который является префиксом другого шаблона)
   * Строится с помощью BFS обхода дерева
3. **Поиск:**
   * Последовательно обрабатывать символы текста
   * При отсутствии перехода следовать по ссылкам отказа
   * При достижении узла выводить все шаблоны из его цепочки выходов
4. **Сложность:** O(n + m + z), где n - длина текста, m - суммарная длина шаблонов, z - количество совпадений

# Карточка 8

**Лицевая сторона:**
Дана строка текста. Требуется реализовать алгоритм сжатия данных с использованием кодирования Хаффмана. Алгоритм должен:

1. Построить частотную таблицу символов входного текста:
   * Определить все уникальные символы в тексте
   * Подсчитать количество вхождений каждого символа
   * Вычислить относительные частоты символов

   * Создать листовые узлы для каждого символа с весом, равным частоте символа
   * Использовать жадный алгоритм для построения дерева: на каждом шаге объединять два узла с наименьшими весами
   * Вес внутреннего узла равен сумме весов дочерних узлов
   * Обязательно создать и хранить граф (дерево Хаффмана) для последующего декодирования
3. Сгенерировать бинарные коды для каждого символа:
   * Код символа определяется путем от корня к листу (0 - левый переход, 1 - правый переход)
